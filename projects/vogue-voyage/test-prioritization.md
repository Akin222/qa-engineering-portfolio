# Test Prioritization Matrix

## Purpose

Test prioritization helps determine which scenarios should receive attention first when testing time or resources are limited.

| Priority | Risk Level | Example |
|---|---|---|
| P0 | Critical | Core customer journey blocked |
| P1 | High | Major functionality unavailable |
| P2 | Medium | Important but non-blocking issue |
| P3 | Low | Cosmetic or low-impact behavior |

## Prioritization Factors

Priorities should consider:

- Business impact
- User impact
- Frequency of use
- Functional criticality
- Likelihood of failure
- Release risk

## QA Principle

Priority should be based on risk and impact rather than simply the order in which defects or scenarios are discovered.
