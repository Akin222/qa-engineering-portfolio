# QBitFlow Requirements Traceability Matrix

## Purpose

The requirements traceability matrix connects important product requirements and business rules to the QA scenarios designed to validate them.

| Requirement | QA Scenario | Priority | Evidence |
|---|---|---|---|
| Valid payment can be initiated | QBF-T001 | Critical | Pending execution |
| Supported network is accepted | QBF-T003 | High | Pending execution |
| Supported asset is accepted | QBF-T003 | High | Pending execution |
| Payment status reflects transaction state | QBF-T005 | Critical | Pending execution |
| Platform fee is calculated correctly | Fee validation scenarios | Critical | Pending execution |
| Checkout expiry is enforced | QBF-EXP scenarios | High | Pending execution |
| Merchant receives expected settlement | Settlement scenarios | Critical | Pending execution |
| Invalid payments are handled correctly | QBF-NEG scenarios | High | Pending execution |

## Traceability Principle

Every high-risk requirement should have corresponding test coverage.

Traceability also helps identify requirements that have not yet been adequately validated and provides a clear connection between product expectations and QA evidence.

## Status

This matrix represents planned QA coverage. Execution status should be updated only when the corresponding scenario has actually been tested.
